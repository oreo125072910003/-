# DSH 核心与原有能力迁移约定

2026-10-25，用户再次明确：小助手的核心永远是 DSH，用户面对的始终是具有持续身份的小助手 DSH。她理解目标、组织工作、调用帮手并交付结果；第三方 API、其他模型和 agent 作为可选能力接入。

默认连接已经登录的 Harness，复用它的模型与账户。产品拥有独立的窗口、任务、成果与配置，不等于另建一套要求用户重复登录的模型客户端。独立 API 配置属于高级可选项。

微信迁移以本机既有 WeChatAgent 的真实源码和接口为准：优先读取原生 GetSelfProfile；现有自定义 hook 不提供该接口时，通过已核验 reader 的 ownWxid 精确查找本人联系人，并再次检查账号绑定。联系人、群与历史来自原 reader，身份映射复用 conversationId。昵称、备注和会话名称是主要展示，数字 ID 放入辅助信息。移植时为每项能力记录原入口、新入口、验证结果和剩余差异。

旧 Skill 与插件保留来源与文件校验，迁入产品管理范围；DSH 原生扩展仍按 DSH 扩展接入，不能把复制文件或健康检查冒充已可实际调用。迁移不修改旧环境中的聊天、凭据与个人配置，不启动第二个 WeChatAgent。
