# 0.3.10 微信文件读取与自主执行修复

日期：2026-10-26（Asia/Shanghai）。用户报告小助手不能读取普通来信和聊天记录中的 Word、Excel，并贴出一次“没有 agent 权限，安装升级需要用户操作”的实际回复。用户要求不操作桌面；完成修复准备后又明确要求先升级当前版本。本轮据此更新小助手，未安装或升级合同助手等其他软件，也未操作桌面窗口、重启微信或 DSH、发送额外测试消息。

## 文件读取

此前链路只将微信图片送入任务输入；文件卡片主要只保留标题，合并转发的文件引用在产品桥接和持久化中丢失，历史记录也没有保留可读取引用。文档解析器原先不支持 XLSX。这些是源码缺口，不能通过让模型“自己找文件”解决。

本次将普通文件、嵌套合并转发及历史卡片的文件引用传过 bridge、controller、SQLite payload 和任务资料。引用绑定已核验账号、原会话、原消息及文件序号。普通文本中伪造的卡片 XML 不会产生文件引用。模型通过已有文档工具即可列出、读取本轮原会话的历史文件，无需新宿主插件或任意电脑路径权限。

固定 Python 子进程查询已有鉴权 reader，并只读取原账号的微信文件缓存。它不启动另一个服务，不操作微信，不下载任意 URL。普通卡片使用原消息 MD5 核对文件；实际转发卡片未携带 MD5 时，只有既有电脑授权私聊可使用微信本地附件索引的唯一内容版本，读取前后重新核对该范围，不新增或扩大授权。多个同名、同大小但不同摘要的版本会拒绝。此索引方式确认本机缓存版本，未声称存在卡片原件的摘要证明。

任务保存独立快照、SHA256、读取状态和校验方式。Word 使用原有有界 DOCX 提取；Excel 新增有界 ZIP/XML 解析，按 workbook 关系和顺序读取工作表、单元格、共享/内联字符串、数字、布尔值和公式缓存值。不运行 Office、宏或公式，不请求外部链接。任务与提示区分实际正文和未取得内容的文件。

真实只读验证使用报告问题的已授权会话。本记录不包含文件名、正文、原 XML、CDN 凭据或聊天标识。共发现 5 个 DOCX、4 个 XLSX 引用，抽查结果如下：

| 来源与格式 | 文件大小 | 实际提取字符数 | 核对方式 |
| --- | ---: | ---: | --- |
| 普通 DOCX | 11369 字节 | 612 | 原消息 MD5、返回内容 SHA256 |
| 普通 XLSX | 12348 字节 | 1110 | 原消息 MD5、返回内容 SHA256 |
| 转发内 DOCX | 11262 字节 | 382 | 既有电脑读取授权、唯一微信缓存索引及内容摘要 |
| 转发内 XLSX | 11009 字节 | 541 | 既有电脑读取授权、唯一微信缓存索引及内容摘要 |

上述样本均未截断。Excel 的缓存公式与外部关系诊断随结果保留；没有重算公式或访问外部资源。解析使用临时快照，检查完成后删除本轮临时副本，原微信文件保持不变。

## 自主执行判断

只读核对用户贴出的那次回复对应会话，确认原先已选过 agent/命令工具，且已启用私聊电脑权限。工具调用链使用小助手 DSH 核心和受控产品命令工具，不能将“没有一个单独叫 agent 的工具”等同于没有执行能力。

本次按每轮实际工具和执行策略提供明确说明：已有本机命令授权时，可以完成用户当前明确要求的软件检查、构建、安装和升级，先核对程序路径与版本并以真实执行结果验证；缺少授权时不伪称已有权限，用户要求不操作时继续遵守。旧命令清理路径还补充持有子进程句柄的有界终止后备，避免 Windows 进程树查询卡住后永远阻塞。没有运行真实软件安装/升级来冒充 agent 实测；本轮实际升级仅为用户另行明确授权的小助手本身。

## 实际边界

单文件 16 MiB、一轮最多 4 份微信文件、总资料 64 MiB；历史列表只覆盖原会话最近 100 条消息。读取器只处理本机已缓存文件，旧 DOC/XLS、加密文档和扫描 OCR 尚未接通。当前缓存版本不能证明没有摘要的转发原件版本，未具备电脑读取授权的会话不会获得此索引兜底。新版实际模型自主安装/升级行为、任意久远历史分页和未下载附件的原生下载未在本轮验收。
