# 0.3.7 本地命令挂起与回复队列修复

日期：2026-10-25，Asia/Shanghai。

## 故障与根因

18:07:19 的原微信会话任务在执行本地命令后挂起。18:09:19 产品发起取消，任务仍长期显示“正在停止本任务”；18:40 和 18:54 的后续任务因此排队，并在两分钟后取消。微信连接和 DSH 宿主均在线，宿主活动任务数为 0，不能以健康检查正常推断产品队列可用。

原生会话日志确认曾通过 PowerShell 启动 HWiNFO64。HWiNFO64 继续运行并持有继承的输出管道，而启动它的 PowerShell 已退出。原命令执行器只等待子进程的 close 事件；输出句柄未关闭时，退出与超时都未能让该 Promise 完成。任务结束时又等待未完成工具操作，最终占住产品唯一执行位置。

在本机使用一个持续运行的合成 Node 子程序复现：设置一秒时限，原实现仍等待约七秒，直到后代程序关闭；已正常退出的父命令还被错误标成超时。

## 修复

- 区分命令进程退出与输出管道关闭。父命令退出后最多继续读取 250 毫秒尾部输出，随后释放本轮管道；通过 outputDetached 记录输出截断边界。
- 已退出命令的 PID 不再用于停止操作，避免向可能复用的 PID 发出终止请求。
- 命令取消、时限和输出上限采用同一终结路径；Windows 进程树终止失败时回退到所属子进程，停止无法确认时返回明确错误。
- 新增真实进程回归，覆盖桌面子程序保持运行时父命令正常返回、后续工具继续工作，以及取消运行中命令后工具服务能够结束。
