# 2026-10-25 小助手任务书进度核对

本表核对原 [40 项任务书](../开发规划/2026-10-25/04_开发任务书.md) 与当日产品代码，目的是回答“现在能用什么，接下来先补什么”。原 [tasks.json](../开发规划/2026-10-25/tasks.json) 保留规划时的状态和阶段安排，本次没有改写；不能直接拿旧状态统计当下进展。

核对时，小助手已经有独立的 XP 风格桌面、任务与成果记录、微信通信页面、多账号邮箱插件、基础文档处理、文献元数据检索和受限文字协作。DSH 宿主已经实际复用原登录完成回复；此前能力目录返回 9 项 Skill、87 项工具。**目录数量表示已登记的能力，逐项操作并未全部实测。** 最新结果见 [0.3.1 开发与验收记录](20261025_0.3.1开发与验收.md)。

**0.3.1 补充**：微信已实现已授权新消息的自动回复、同聊天固定工作空间和原生会话恢复，以及受限图片/文件发送。246 项测试、64 个 JS 检查、最终安装包桌面测试通过；真实 DSH 两轮同会话记忆与分类通过，真实微信账号、昵称及读取接口核验通过，原授权范围保留。媒体实际外发仍未验收，功能未达到 WeChatAgent 全量。以下任务状态仍保持 4 项主体完成、28 项部分实现、8 项尚未实现。

## 怎样理解本表

- **主体完成**：任务的主要开发交付已有实现与相应验证；不表示整个产品已经通过真实业务、安装升级或长期稳定性验收。
- **部分实现**：已经有可使用或可验证的产品代码，但原任务的范围或验收条件仍有明确缺口。
- **尚未实现**：产品中尚无这项工作的实质闭环；现有名称、说明、旧工程代码或相关基础模块不算实现。

按此口径，**4 项主体完成，28 项部分实现，8 项尚未实现**。这不是“完成率”；任务大小不同，尤其长期项目、记忆、主动跟进和综合验收仍有较大工作量。M0—M7 是原计划的依赖阶段，不能根据某个后期功能已有雏形，就认为前面的阶段已全部验收。

## 最影响“真正成为我的小助手”的三条流程

### 1. 记住一件事，经过多次交流继续做

用户说“继续昨天那个课题”“把刚才的材料按新要求改一下”，她应当知道对应项目、原始资料、已确认事实、当前成果及待补信息；重启后也能继续。

现在微信同一聊天已经复用固定工作目录和原生 sessionId，真实隔离样例的两轮续聊与原生分类通过。桌面工作台每次仍以新任务提交，没有选择旧对话并继续的完整操作；设置中的名字与人格也不等同于可查看、可纠正、可删除的长期记忆。

优先依赖：T09 对话继续入口 → T10 等待资料/检查点 → T26 有来源的项目记忆 → T27 项目与任务关联。第一份验收样例应是：添加资料、生成初稿、补充要求、重启、继续修订，且不重复创建工作或混入别的项目资料。

### 2. 从微信或邮件收到资料，一直做到可交付成果

用户选定来信或微信资料，交给她整理、拟合同或写材料；她列出缺项，收到补充后生成可编辑文件，供用户审阅，再按明确指令交付给正确的人。

现在接收/查看、微信文字自动回复与手动发送、邮件附件另存、简单 Word/PDF 导出等环节已经存在；微信图片/文件有选择授权和受限界面发送，微信和邮件各自保存发送状态，不明结果不会自动重发。但它们还没有形成通用的“资料进入同一任务 → 正式文档核对 → 文件交付 → 原来源回执”闭环。真实微信外发、真实邮箱、正式合同模板与任意文档版面也不能从模拟 smoke 推断已经验收。

优先依赖：T17/T21 可信来源 → T20 受控附件导入 → T22–T25 工作能力 → T11 文件与投递关联 → T18/T33 真实会话验收。先完成一个真实业务样例，比同时增加大量工具名称更有用；首个样例可选“授权邮件附件生成合同草稿和核对表，用户审阅后回到原邮件草稿”。

### 3. 交代以后，到了时间她会跟进

用户说“明天下午提醒我交材料”“每天看看有没有这类重要邮件，有变化再告诉我”，她应当保存规则，展示下一次执行时间，支持静默和取消，并在睡眠或断网后按明确规则处理错过的执行。

现在没有产品自己的计划任务存储、调度器或规则界面，邮箱同步仍由用户手动触发。原有 Skill 名称中的“跟进”，以及可以写出计划文字，都不等于已经能主动运行。

优先依赖：T08 计划存储 → T10 可追踪执行 → T11 通知去重 → T22 邮件事项 → T31 调度与提醒。第一份验收样例应覆盖按 Asia/Shanghai 时间执行、无变化保持安静、取消后不再运行、电脑关闭时不冒充已完成。

独立外部 agent/模型接入也未完成，目前的“写作—审查”“双路分析—审查”是同一 DSH 核心下的不同角色。应在上述基础流程稳定后补 T28/T29，并保留 DSH 作为组织任务和最终交付的核心。
