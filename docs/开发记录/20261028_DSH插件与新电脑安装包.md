# 小助手与专用微信 DSH 插件 1.1.0

用户要求把专用微信和小助手整理为同一个 DSH 插件，并明确还要能拿到新电脑安装。

## 交付形态

- 沿用 `xiaozhushou-harness-host` 包名，将原 DSH 连接组件扩展为内置小助手服务和工作台的插件；源码在 `packages/dsh-plugin`，保留原独立桌面入口。
- 使用 DSH 的 Web Server、客户端插槽、现有登录、原生会话与工具授权。服务与 DSH 同进程运行，不启动第二个小助手或旧 WeChatAgent 自动回复程序。
- DSH 的会话标题栏和设置提供入口，工作台嵌入 DSH 面板。原微信、任务、邮箱、技能、MCP、合同和文件操作使用主工程原代码。
- 原数据目录会自动发现，包括旧启动器造成的目录重定向；存在多份数据库时要求明确选择，不合并。原桌面持有锁时不抢占，退出后重试可沿用数据。
- Windows 凭据适配读取旧 Electron v10 加密记录，也支持当前用户 DPAPI。只读兼容检查成功读取了本机两条既有加密记录，未回显内容、未重写凭据。

## 新电脑完整版

`npm run package:dsh:full` 在 `dist/dsh-plugin/1.1.0-full` 生成 TGZ、候选目录、manifest 和 SHA256。程序组件共 762 个文件、991,773,843 字节；TGZ 约 428 MiB，最终大小和摘要以生成的 manifest 为准。

内含匹配的微信 4.1.10.27、原已核验的连接 DLL、Python 3.13 及读取依赖、reader 代码、原生连接组件和合同程序。微信资产仅白名单读取程序、精确版本目录和连接 DLL，排除原 native token、媒体根配置及任何账号状态；不复制原电脑的微信数据、读取密钥、DSH 登录或个人配置。

新电脑须有兼容的 DSH（本轮验证为官方 0.2.1-rc.3）并自行登录；首次插件安装需要联网安装 JavaScript 依赖。通过 DSH“插件 → 添加插件 → 安装第三方插件”，在“包名或地址”填入 `file:` 加 TGZ 的本机绝对路径。正式 CLI 亦可安装。

首次向导将组件校验并复制到产品自己的 `wechat-environment`，生成新令牌与动态端口，打开匹配微信，再识别和验证用户选择的账号。登录与手机确认由用户完成；若读取验证要求重新登录，按界面说明退出账号后重新登录。实时微信账号核验分别位于读取凭据捕获前和提交前。只保存当前 Windows 用户加密的读取凭据；首次自动回复关闭、允许聊天为空。

读取验证支持取消，插件卸载或退出时终止自己启动的验证任务。向导不结束既有微信进程、不改变系统微信入口，也不覆盖既有小助手连接。

## 验证证据

- 485 项自动测试通过，0 失败；日志 `dist/dsh-plugin/final-full-tests.log`。新增覆盖真实产品服务 HTTP、成果持久化、旧实例锁与身份保留、请求来源、凭据兼容、新目录准备、独立新令牌、资产篡改、账号不匹配、首次仅连接和取消。
- 完整包在全新临时目录实际准备成功，逐文件摘要核对、内置 Python 的 reader 及依赖导入、原生连接 DLL 加载通过；没有读取账号或启动微信。证据 `dist/dsh-plugin/portable-smoke/report.json`。
- 使用完整包内实际服务和原产品界面完成任务/成果、设置持久化、微信/邮箱/能力页、首次向导和窄窗口验证。证据 `dist/dsh-plugin/ui-smoke/report.json` 与截图。
- 使用官方 DSH 0.2.1-rc.3 CLI 在隔离的 Web profile 实际安装完整版，启动内置服务，经过真实 DSH 设置入口打开嵌入面板。证据 `dist/dsh-plugin/official-verification-1793126660248/report.json`。宿主自身 `/favicon.ico` 404 单独记录；插件入口与面板无页面错误。
- 未切换日常 DSH profile 或正在运行的旧小助手，未更改原微信数据；未主动发送测试微信。

## 验收边界

“新目录初始化成功”不是在第二台真实电脑完成微信登录与收发的证据。新电脑的微信登录、数据库同步、读取连接和真实收发仍需实际登录后逐项验证；本轮不声称已经通过。

“完整版”指安装所需的配套组件完整，不表示原 WeChatAgent 所有历史功能已新增迁入；既有功能边界仍见 `packages/wechat-bridge/功能迁移对照.md`。本轮未更换推理核心，也未引入绕过 DSH 的模型循环。
