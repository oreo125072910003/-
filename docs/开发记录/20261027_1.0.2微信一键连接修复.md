# 小助手 1.0.2：修复微信冷启动连接

2026 年 10 月 27 日。用户反馈微信已经登录，小助手仍然连接失败。

## 已确认的原因

此前助手通过系统默认入口打开了 `C:\Program Files\Tencent\Weixin\Weixin.exe`，实际版本为 **4.2.0.8**。现有微信连接适配的是原环境中已配置、已部署连接组件的专用 **4.1.10.27** 客户端。系统微信登录成功，不能使另一个版本的本机连接接口启动。

产品旧的冷启动流程只确保消息读取服务运行，没有负责启动匹配的微信客户端。因此，即使配置已经导入、自动连接已经打开，也可能长期停在接口不可用状态。此前浏览器自动连接的成功验收并不能证明微信连接成功。

## 修复

- 微信连接前先检查专用客户端，而不以读取服务健康代替客户端健康。
- 校验已配置程序的版本、腾讯签名、既有连接组件摘要、本机令牌一致性和产品媒体目录；只启动已经准备好的匹配客户端，不重新安装组件，不启动旧自动回复程序。
- 启动后核对本机接口身份、进程与初始化状态，再连接消息读取服务和原有产品会话。
- 另一版微信仍在运行时显示“等待退出另一版微信”，保留用户当前客户端。专用微信需要手机确认时显示“等待微信登录”，完成后自动继续连接。
- 保留账号、接收范围、自动连接和自动回复选择；不通过重新导入或放宽账号核验来消除错误。
- 清理启动子进程继承的 PowerShell 7 模块路径，确保 Windows PowerShell 的签名检查可用。
- 桌面合成验收明确注入模拟的客户端准备步骤，并检查启动脚本已在安装包中展开。正式用户数据仍执行真实校验。

## 本机处理与验证

用户正常退出了系统微信 4.2.0.8，修复后的启动器实际打开专用 4.1.10.27。连接组件就绪后，由用户完成手机登录确认；真实接口确认当前只有一个账号，且与读取服务账号一致。

使用 **1.0.2 安装包内的实际服务代码、原产品数据与 Windows 加密凭据** 完成连接，结果为：

## 后续使用

从小助手的“连接我的微信”进入。自动连接开启时，小助手启动后会准备专用微信并继续核验；微信本身要求的手机确认仍由用户完成。若同时打开另一版微信，界面会说明需要先退出哪类客户端，避免把“客户端已登录”误显示成“产品收发已连接”。
