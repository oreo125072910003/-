# 0.3.9 微信 Hook 附件实发与离线验收

日期：2026-10-25（Asia/Shanghai）。用户要求使用 Hook 实现图片、文件发送，并授权向一个指定测试私聊发送一张合成 PNG 和一个合成 TXT。两份附件各实发一次，均已核对新出站数据库记录、非零服务器 ID 与精确内容摘要。真实账号、聊天名称、消息 ID、凭据及原始 XML 不写入仓库。

## 实现

- 桥接默认调用已有微信进程的鉴权 `/SendImgMsg`、`/SendFileMsg`，复用原账号、联系人映射、reader 和发送互斥；未启动第二个 WeChatAgent，没有 UI 自动回退或未知结果重发。
- 发送对象由微信原生工厂构造，分别使用图片、普通文件的 owner/vtable，以及客户端 UTF-8、UTF-16 字符串赋值函数和分配器。未启用上游手工拼接的 `SendImage`。对象和异步参数引用保留至进程退出，每类最多 128 份；达到上限明确拒绝。
- 原生实现只接受本机已核对的 4.1.10.27、唯一当前账号及 Weixin.dll SHA256 `f487e4f56930456a25fb0d7b058c77e2dcd364e268d49bdfff4dc0e3be26ba36`。图片工厂 RVA 为 `0x1C4CE70`，文件工厂为 `0x22A92B0`。
- 受信任启动脚本在客户端关闭时写入本地产品目录清单，HTTP 请求不能更改根目录。快照摘要、逐级文件锁、严格路径和原生持久防重继续生效。图片限 PNG/JPEG、8 MiB；普通文件限 50 MiB。
- 原生接收响应始终为 `delivered:false`。产品要求唯一新出站数据库行、时间与身份匹配、非零服务器 ID 及精确 MD5；文件还要求 appmsg 类型 6、名称和长度匹配。

## 真实发送与发现的修正

| 合成样本 | 内容证据 | 实际结果 |
| --- | --- | --- |
| PNG，640×360、12653 字节 | MD5 `571437a6ad76c3e5685ef80d1ddd9c7f` | 首次提交即匹配图片摘要与服务器回执 |
| TXT，103 字节、中文文件名与正文 | MD5 `a38ada961e7348bfbdcfe31677170b8e` | 微信发送成功；首次桥接核验漏读摘要位置，修正后只读核对同一条原始回执 |

实际文件 XML 将 MD5 放在 `/msg/appmsg/md5`，原先代码只覆盖 appattach 内的摘要和 appmsg/filemd5，导致 TXT 虽已发送却超时显示未确认。修正后收集 appmsg 中全部 `md5/filemd5`，要求至少一个且每个都与快照一致；名称、大小、类型、时间、方向、身份和服务器 ID 的要求继续保留。增加真实结构的回归样本，并拒绝缺失、错误或互相矛盾的摘要。

核对 TXT 时没有重新调用发送接口、生成新投递 ID 或清除账本。只读核验结果写入被忽略的本地验收记录；首次原始账本仍保留当时的未知状态，用于防止重放。两份实发来自源码桥接默认 Hook 路径，不等同于最终安装包界面实发。

## 登录与运行维护经过

重载微信后曾出现客户端自身的升级失败提示，随后登录页二维码空白。用户授权恢复已核对的旧 Hook 并恢复原目录写保护；回退成功，但用户仍报告空白。之后用户自行恢复登录。再次切换候选媒体组件后，健康接口报告唯一已登录账号、两个媒体入口就绪，登录状态保留。现有证据不能确定此前二维码空白的原因。

维护前确认没有 queued/running/validating 任务，数据库完整性为 `ok`，通过正常退出路径停止原产品并保存一致备份。原 DSH 身份、会话映射及任务数据保留。实发前恢复原有 reader，未增加一套服务；同时重新打开已安装的 DSH。

两次桌面观察被用户 Esc 中断后均停止电脑操作。用户随后明确要求“继续测试，别操作我的电脑，有问题问我”；之后只运行独立合成测试、读取构建内容和修改工程文件，没有操控窗口、启停现有软件或新增微信外发。

最初给用户直接 EXE 入口时遗漏原数据目录参数，用户报告“微信账号待识别”，读取服务没有产品订阅。随后请用户自行退出并通过项目的 `启动小助手预览版.cmd` 重开，助手没有替用户操作。只读状态确认正式桌面 0.3.9 使用原数据目录、DSH 宿主 0.3.6 连接正常；Hook 唯一账号与 reader 一致，两个媒体入口就绪，reader 已有产品订阅。原数据库完整性仍为 `ok`，保留自动连接/回复设置、原 4 个私聊和 3 个群，缓存账号资料与当前微信一致。本次只验证运行状态，未新增模型对话或测试附件外发。
