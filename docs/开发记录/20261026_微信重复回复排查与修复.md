# 微信一条消息收到多套答复

## 原因与证据

2026-10-26（北京时间）排查确认：桌面小助手与旧运行目录中的 `social-bridge.js` 同时响应同一微信账号的相同授权会话。桌面使用产品自己的持续 DSH 会话，旧桥接使用另一套 DSH 会话、人格和消息缓冲，答案因此可能矛盾。旧桥接还会分条发送文字与表情。

一个实际时间序列：02:09:50 接收到一条消息；桌面发送记录显示 02:09:53 发出答复；旧桥接日志显示同一会话在 02:10:00 和 02:10:02 分别发送了自己的两段答复。不是桌面重复提交了同一条出站记录。

旧桥接的发言也不属于桌面的自动发送回执，可能被桌面判断为人工接管，从而取消正在生成的桌面任务。

## 修复

- 增加 `runtime.replyOwner`，允许 `legacy`（兼容原默认行为）和 `desktop`。
- 配置准备流程把归属写入生成的 `bridge-config.json`，重复准备不会恢复旧自动回复。
- `desktop` 模式下，服务管理器仅保留读取服务，停止属于本安装的旧 `bridge` 与旧 `adapter`，不启动旧回复链路；桌面使用现有进程内微信收发实现。
- 旧回复入口在初始化前检查归属，属于桌面时直接退出，防止手动或其他旧入口重新拉起抢答。
- 在当前真实运行目录应用 `desktop` 模式，备份原配置和三个变更文件后停止两个身份核实过的旧进程。桌面小助手、微信客户端、读取服务和 DSH 未重启，聊天数据未删除。

## 验证范围

自动化验证：回复归属配置校验、配置重复生成保留归属和会话数据、旧回复进程启动被阻止；已有微信自动回复与持续会话测试一并执行。PowerShell 服务管理器通过语法解析检查。

真实运行验证：两个旧进程已退出；读取服务状态成功、无最近读取错误；DSH 宿主健康检查成功；直接运行旧回复入口会提示归属桌面并退出。

尚未代替用户向微信发送测试消息。下一条真实消息是否只产生一套答复，需要在实际聊天中确认。

## 恢复

运行目录 `state/reply-owner-backups/20261026-021558` 保存了修复前的相关文件。若需要切回旧版独立回复，必须先退出桌面小助手，再将 `runtime.replyOwner` 改为 `legacy` 并通过旧服务管理器启动，避免再次并发回复。
