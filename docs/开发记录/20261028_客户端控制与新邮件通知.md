## 已定位的问题

- 原产品工具没有原生窗口枚举、观察、点击或键盘操作；Playwright 只能操作网页。
- 截图工具原来只返回成果元数据，宿主只渲染文字，模型没有收到截图像素。
- 原微信私聊未选中邮件工具，尽管本机已有邮箱账号，模型也无法读信。
- 原地更新同一个 file: 插件目录时，安装缓存曾保留旧的 revision 文件。改用新的产品自有安装目录，并核对安装后的入口文件和实际 health。
- DSH 的工具输出 schema 只支持有限子集。截图输出必须显式声明嵌套对象和枚举的 string 类型，不能使用 maxItems。新增真实运行时 schema 检查，防止仅通过模拟注册测试却不能建立原生会话。

## 实现

- `packages/desktop-control`：Windows 自带 .NET Framework 编译的固定操作组件；没有脚本执行入口。工具按本轮权限运行，窗口 ID 来自枚举，操作绑定进程身份、边界及单次、60 秒有效的观察编号。输入后返回新截图与控件信息；遮挡、焦点变化、超时或结果不明时要求重新观察。密码框、系统安全窗口、终端和 ChatGPT 不自动操作。
- `xiaozhushou_desktop`：窗口枚举、观察、点击、普通文字、按键和滚动。继承已有桌面或显式私聊电脑权限，不授给群聊或普通邮件任务。
- 截图预览以有界 JPEG 字节、校验摘要传回宿主，经原生附件服务转成 image block。任务结束后按实际 tool/result 位置卸载图片并持久保存，不把文件名当作视觉输入。
- `apps/service/mail-monitor.mjs`：每 60 秒只读检查邮箱。首次成功同步与 UIDVALIDITY 变化建立静默基线；之后按 UID 增量收取，支持分批补齐。通知包含发件人、主题和简短正文，收件目标固定为主人选定的私聊，不由邮件内容决定。
- 通知队列与游标持久保存，发送复用原微信出站账本和服务器回执。断线等待原账号恢复；送达不明确时不自动重发。邮箱服务仍不自动标记已读、移动、删除或回复邮件。
- 邮箱页增加通知开关、接收私聊、上次检查及异常状态。配置通过原可信桌面接口保存。
- 只为最近已核验的原私聊补充邮件工具与原生客户端工具，没有给其他聊天批量扩权。数据库和宿主安装均已在产品数据目录内备份。
