# 2026-10-25 小助手 0.3.1 开发与验收

0.3.1 是继续使用原产品数据的开发预览版。本轮按用户要求优先完善微信基础通信，再与 WeChatAgent 源码逐项比较。小助手始终由已经登录的 DSH 提供核心能力，没有要求重新提供核心 API Key，也没有启动第二个 WeChatAgent。

## 本轮交付

| 使用场景 | 已实现的行为 |
| --- | --- |
| 收到微信新文字 | 已授权聊天、账号和读取接口核验通过后，自动调用 DSH 并把完整成功答复发回原聊天；只处理本次连接后的新消息。首次自动导入默认启用，可在微信页暂停。 |
| 连续聊同一件事 | 同账号、同聊天使用固定工作目录和原生 sessionId；各聊天独立，同聊天顺序执行，重启不补发历史。失败初始化不会把无效 sessionId 保存为后续会话。 |
| 在 DSH 找到对应对话 | 正式 workspaceRegistry 接口创建/复用分类、核验原生 cwd 后绑定会话；保留已有自定义名称和归档状态。 |
| 在群里叫她 | 基础 mention/hybrid 策略支持真实 @ 本人、唤醒词、拍一拍和引用本人；无需回应时保持安静。没有宣称已迁入全部原社交策略。 |
| 主人接手回复 | 手动回复、可信本人新发言、断连、换号、撤权或关闭自动回复会取消待发任务。已登记自动答复的回显不会误取消下一条排队消息。 |
| 发送图片和文件 | 专用选择器授权、产品快照、摘要检查和持久投递记录；图片上限 8 MiB、文件 50 MiB。当前通过受限微信界面路径提交，实际外发仍未验收。 |
| 看发送结果 | 有内容匹配的数据库服务器回执才标为送达。明确尚未提交时显示“未发送”，允许主人处理后点一次新请求重发；结果不明则保留待核对，不自动重复发送。 |
| 查看和管理 | XP 微信页分为消息、好友群聊及连接设置，文字与附件区域清楚分开；显示自动回复阶段、真实名称、附件大小及投递状态。 |

## 与 WeChatAgent 对比的结论

完整逐项表见 [功能迁移对照](../../packages/wechat-bridge/功能迁移对照.md)。已接通核心通信、DSH 自动回复与持续聊天，附件有受限实现，**并未全量迁移**。

当前原生 Hook 没有普通图片 `POST /SendImgMsg` 路由，实际返回 404；`SendImageMsg.cpp` 是源码文件名。当前图片/文件路径要求微信已经打开目标聊天，而且能核对准确标题、空输入框、附件预览和发送按钮。客户端 UIAutomation 不可读、重名、焦点变化或图片重编码，都可能阻止操作或使回执保持未知。未向真实联系人投递，不把这一项标为真实验收通过。

原有主动聊天调度、群友长期记忆、微信会话搜索和网页阅读授权、自动上下文压缩、逐聊天 MCP/Skill 授权、完整人设/图库/分组管理、文件接收下载与全部卡片呈现仍有缺口。持续会话不等同长期记忆，自动回复也不等同无来信时主动行动。
