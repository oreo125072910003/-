## 实际工具故障原因

本轮只读检查时，新宿主 11234 在线，103 项工具、12 项 Skill，既有 DSH 登录和文字能力有效。产品设置没有保存 `dshOwnerGrants`，旧微信逐聊天授权也未接入新产品任务；此前 `grantsForTask` 对微信固定返回空。因此目录可见与本轮可执行不一致，助手仍可能沿历史设定口头承诺操作。

外部 pcbridge 8765 在线且登记 16 项工具，真实临时文件读取、列目录和公开比分查询通过，不能把本次问题统称 MCP 断线。实际副本仍比仓库旧，业务错误映射、协议协商、有界读取及旧外发逻辑有部署漂移。详见同日 MCP 排查记录。

本轮将业务工具、电脑控制和文字协作分开：普通任务显式选择工具；微信按已核验账号及稳定会话绑定授权；电脑控制需要单独私聊确认；文字协作始终无工具和 Skill 执行授权。默认不向群或其他聊天开放电脑控制，不依据正文中的“我是主人”授予权限。

## 本聊天修改

- F01：可信 worker adapter 清空父任务工具与 Skill，固定 `worker-text-only-v1`。宿主再次清空并在最终 guard 拒绝，客户端在旧宿主未确认此策略时不提交。
- F08：共用规范工具身份/能力分类，识别 MCP 命名空间和原有控制别名。未知工具保持不可用并显示原因；普通业务工具和独立电脑控制不能混作一项授权。
- 原逐聊天授权：只从与当前连接吻合的本机旧工程读取，绑定第一个已核验账号；只迁入当前允许聊天，不覆盖已保存选择。原不可用选项保留但不激活，编辑有效工具不会被旧选项卡死。
- 独立电脑控制：默认关闭，只允许私聊、且只限该会话原先明确选择的 pcbridge 电脑工具。桌面必须明确确认才能启用，模型内容和其他聊天不能调用该设置；撤权取消相应在途任务。实际开启状态以本轮用户确认及交付证据为准。
- F12 服务部分：新增 `getTaskReplyText(taskId)`，仅成功任务、所属完整成果、路径/大小/哈希核对后返回全文；摘要仍只用于概览。邮件与微信手动草稿由 UI 接续任务接线。
- D02 源码部分：看门狗移除按名称匹配批量终止进程；明确目录/解释器、独立互斥，检测源摘要及工具数。已存在不健康进程/端口时记录待诊断，不擅自杀进程。实际运行看门狗和计划任务未因源码修改自动更新。
- 模型能力说明：每轮只声明实际授予且可见的能力；无工具时明确不能实时查询、操作电脑、截图或承诺稍后调用。

## 并行分工与对话恢复

旧微信开发对话本轮在执行前遇到 `invalid_encrypted_content`，指向旧加密消息。原记录保留，没有改写 Codex 数据库或加密历史；建立干净接续对话负责 F02/F03/F07/F09/F10，并验证其已开始执行。原 UI 对话因自动任务只读权限不能写入，核查结论已交给另一个可写接续对话，负责 F11–F14、完整草稿和授权界面。pcbridge 对话负责 F04–F06、部署差异及真实底层探针。

修改范围分离，只有 renderer 的精确函数需要协调暂存；不覆盖共享工作树、不把其他人的未完成改动误作发布。各模块结果以对应测试、提交和最终集成记录为准。
