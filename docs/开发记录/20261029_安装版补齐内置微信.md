# 安装版补齐内置微信

用户反馈 1.0.6 的 Windows 安装版内没有微信。核对实际产物后确认：143059540 字节的独立安装器只带工作台，专用微信和首次连接向导仅存在于 DSH 完整插件，未满足用户需要一起安装的意图。上一轮“全部完成”的说明范围不准确。

本次修正为桌面 1.0.7、DSH 插件 1.1.5：

- 独立桌面默认构建完整微信组件，使用与 DSH 相同的 bundleWechatComponents 白名单，不新增第二套微信或自动回复程序。专用微信 4.1.10.27、匹配连接组件、Python 与 reader 只放入 resources/companions，不重复塞入 app.asar。
- 组件共 762 个文件、991778701 字节。安装包不包含原电脑账号、令牌、密钥或聊天；每台电脑首次准备生成独立连接配置。DSH 核心仍独立安装并复用原登录。
- 微信页在未导入连接时明确显示“安装包已包含微信”与“准备并连接微信”，四步为准备、打开、识别、验证。已有连接继续沿用；缺组件时诚实显示缺少，不把“导入旧连接”当作新电脑的必经步骤。
- 独立桌面与 DSH 共用 renderer/wechat-setup.js/css 和 packages/wechat-bridge/portable.mjs。原 DSH portable 模块只包装导出，旧重复向导文件删除。
- 桌面增加五个固定、受主窗口核验保护的准备接口。目录、程序和服务来源由可信主进程固定；界面不能通过参数替换。绑定仅接受已识别的账号标识，长等待之后重查当前连接与取消状态，防止覆盖用户期间接入的旧连接。
- 新电脑登录、手机确认和实际会话授权仍由用户完成，首次自动回复关闭、允许会话为空。不会替主人登录或发送测试消息。

## 验证要求与已完成检查

完整源码回归 551/551，157 个脚本语法检查通过。新增/保留覆盖原连接保护、取消后迟到结果、伪造账号、界面参数注入、窗口/子框架/外部 URL 的调用拒绝。旧 VM 夹具补齐浏览器事件 API，原业务断言未变。

共享向导已完成真实 Electron、真实 preload 加合成 IPC 的四步检查，包括重复点击只准备一次、步骤前置、账号纯文本、已有连接隐藏、缺组件提示及旧宿主首次拒绝后停止重试。报告在 dist/wechat-setup-ui-1.0.7，未打开真实微信或读取个人账号。

打包与安装验收已加强为：缺少组件、摘要不符、轻量包、混入运行数据或重复文件路径时拒绝完整安装器构建；实际安装后逐文件校验微信组件，必须通过真实 UI 点击准备并导入内置 Python/reader，卸载后重新核对生成的微信环境仍保留。不能再只凭工作台 EXE 和 app.asar 通过就认定完整。
