# 0.3.8 微信图片和文件 Qt 界面兼容适配（实发验收待完成）

## 问题与修改

本机微信 4.1.10.27 的 Qt 窗口只暴露根窗口和一个窗格，旧附件脚本无法读取标题、输入框和发送按钮。前台切换也可能被 Windows 拒绝，已有尝试记录为 `WECHAT_ATTACHMENT_UI_WINDOW_CHANGED`。

- 保留 UIAutomation 路径；为已核对版本增加本机 Windows 简体中文 OCR 和截图校验，不安装第二个微信服务，不修改原 Hook 或 DSH 核心。
- 使用原有账号、授权会话和联系人映射；标题去空格后也检查联系人、群聊和别名冲突。按首个非空字符扩大联系人搜索范围，结果触顶时拒绝。
- Qt 路径识别目标标题、搜索结果、输入区分隔线和空白区域；仅点击新截图所确认的位置。再用只读复制检查不可见草稿，不删除或覆盖原有草稿。
- 修复前台切换，允许粘贴后由主窗口拥有的附件预览窗。剪贴板只包含本次已验证的一个文件路径，粘贴一次，识别发送按钮后点击一次；不补按回车、不自动重试。
- 图片预览存在“原图”选项时核对复选状态；所有最终结果仍需原有精确内容摘要、文件名/大小（文件）、新出站数据库行和真实服务器 ID。
- 兼容脚本随 ASAR 解包，安装包 smoke 检查其存在；新增加渲染文字 OCR、草稿、缩放、禁用按钮和重名保护的离线测试。

## 验证与当前状态

- 初次完整测试：394 项通过；86 个 JS 源文件语法检查通过。
- 扩充空格重名案例后，相关 70 项测试全部通过。
- 0.3.8 Windows 安装包已构建；独立临时数据的安装包 smoke 通过。
- 真实微信截图的离线标题识别通过，原生小字号需放大后识别；带鼠标效果的输入区截图不会被误认为干净草稿。
- **尚未完成真实图片、文件发送验收。** 桌面控制在用户 Esc 中止后仍返回停止状态；用户已明确恢复测试并确认具体合成材料和目标，但当前执行轮仍被工具中止。没有因此改走未经核对的直接 UI 脚本。
- 当前正式运行实例保持 0.3.7，未切换生产实例、未修改用户聊天数据，也未向真实联系人发送测试附件。
