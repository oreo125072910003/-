## 图片链路

产品从已保存的微信来信取得图片引用；消息正文、公开任务参数中的路径、URL 或自造图片字段都不能成为图片来源。执行时复核原来信、账号、会话和图片 ID，再复用原 `resolveImage` 读取会话绑定的图片。

每轮最多 4 张，每张最多 768 KiB，支持 reader 已规范化的 PNG/JPEG/WEBP。微信服务、宿主客户端和宿主共用字节校验，核对 Base64、长度、文件头和 SHA256。成功图片在独立任务资料目录留下快照；清单只保存来源、摘要、大小及读取状态，不把 Base64 塞进任务数据库。

宿主通过实际 `llm.resolveModelInfo` 和 attachment 服务判断能力，使用原生 `attachments.saveImages/saveImage` 和 image block 进入同一个 DSH agent，不增加核心 API Key 或新推理循环。图片顺序与摘要参与任务幂等，HTTP 总量最多 5 MiB，文字仍独立限制为 256 KiB。

无法读取的图片会明确标记未提供画面，保留其余成功图片；不让模型假装看懂。任务取消或失败也保存读取清单，未处理项标明取消或未读，迟到的 reader 结果不会继续写资料或启动模型。

只有实际本轮结束后才卸载本轮图片并保存原生会话。停止未确认时继续保留会话占用；卸载或保存失败的会话持久标记待处理，重启也不能直接续用。兼容 Harness 在模型重试时已经卸载图片、或压缩移出部分消息的情况，只对仍有效且未卸载的本轮图片追加清理事件。

## 图片与文件发送修复

受限客户端发送路径此前把“控件不支持读取输入值”和“输入框确有草稿”一起报为已有草稿。本次改为独立错误，界面使用已有对应提示。

固定发送脚本在最终授权后再次核对输入区，若明确报告尚未粘贴且仅属于上述两种错误，投递仍记为 `attempted:false`、`rejected`，允许处理后由用户明确重新发送。已粘贴、缺少明确证据、超时、协议异常和未知结果继续保留不确定状态，不自动重发。目标、附件预览、媒体类型、文件摘要及服务器回执校验没有放松。

宿主安装先通过正式准备函数生成 revision `9fa8e626be6c07b5`，保留产品内旧模块备份，再运行官方 `dsh plugin --profile desktop add file:<产品插件目录> --ignore-scripts`。安装器返回 `ERR_PNPM_EPERM`：运行中的 `dsh-pet` 文件无法替换。失败日志保留，没有手动删除 profile 插件或改写 manifest 绕过安装器；当前原宿主仍在线，图片能力为 false。正式安装及真实视觉验收完成后再补本记录。

## 与 WeChatAgent 仍有的差异

- 图片与文件真实发送尚未验收；原生图片生产路由仍禁用，现有路径依赖可读取的微信 UI 和内容匹配回执。
- 收到普通文件目前只保留标题，尚无可信下载、另存为及交给 DSH 阅读的闭环。旧缓存按文件名查找的方式缺少可靠绑定，不能直接当文件下载接口。
- 微信会话的工具授权、主动聊天、长期成员记忆、自动压缩策略和完整素材管理仍待迁移。图片终态卸载不等于实现自动上下文压缩策略。

逐项基线见 [功能迁移对照](../../packages/wechat-bridge/功能迁移对照.md)。后续先完成真实图片/文件投递、接收文件闭环及必要工具授权，再扩展其他工作能力。
