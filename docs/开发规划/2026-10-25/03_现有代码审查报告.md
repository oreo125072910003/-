审查日期：2026 年 10 月 25 日。审查基线：`6403cb2662d8d8288386f8a44ef9a874c553a516`。审查范围为主工程 `代码/项目`、`代码/pcbridge` 和 `代码/合同助手`，未把 `代码/项目-安装包副本` 作为另一套持续开发来源。

## 审查结论

现有工程具备微信通道、网页控制台、Harness 社交会话插件、按聊天的工具与技能授权、电脑工具及合同 MCP 接口，适合继续演进。主要缺口是产品层的独立桌面入口、可靠任务与身份传递、多账号插件体系、受管理的扩展机制以及可重复构建。应保留已完成的消息解析和发送回执逻辑，在边界外逐步重构。

本报告是结构与关键路径审查，附有四项隔离函数复现；它不等同于全面渗透测试、真实微信联调或合同业务验收。未读取或展示个人密钥与聊天内容，未导入执行项目模块，未调用模型或连接真实邮箱。

## 已确认问题与修复任务

严重度按个人助手的实际使用影响划分。P1 是进入日常试用前应解决的问题；P2 是产品化前应处理的问题。未发现需要据此宣称系统已经被入侵的证据。

### CR01 后台任务仅保存在进程内存

**P1，可靠性。** `代码/pcbridge/mcp_dsh_server.py:352` 定义 Job，`:405` 使用全局 `JOBS` 字典，`:707` 至 `:717` 创建并启动线程。任务和通知状态主要保存在对象中。服务重启后，这批后台任务无法从该字典恢复或继续追踪，也没有持久投递记录可证明结果是否已经通知。

触发条件是任务运行期间桥接进程崩溃或重启。修复：持久化 Task、Attempt、Artifact、Outbox；恢复时区分可重试的只读任务和已经可能产生外部动作的任务。不得自动重放未知结果的发送或生成动作。对应 T08、T10、T11。

### CR02 发送上下文由最近聊天推断

**P1，路由正确性。** `mcp_dsh_server.py:1896` 扫描全局近期聊天，`:1936` 自动推断目标，`:1957` 在没有显式 target 时使用该结果。已有多聊天保护会在歧义时回退主人私聊，这比任意发群更稳，但不能证明目标就是派发本任务的聊天。

两个聊天交叉来信或长任务完成时，目标可能与任务来源不同。修复：创建任务时绑定不可变的 channelAccountId、conversationId、requesterId、replyTarget；出站执行端重新检查权限与目标。歧义时保留结果并提示选目标，不自动换收件人。对应 T07、T11、T17。

### CR03 网页工具存在两套不同的网络限制

**P1，能力边界。** `mcp_dsh_server.py:2238` 仅验证 http/https，随后进入 `_fetch_webpage` 或浏览器；`:2169` 起使用自动跟随重定向的 urllib。该路径没有主项目网页工具中的私网地址、DNS 和逐跳重定向校验。隔离复现 R03 显示 `http://127.0.0.1:9876/private` 被传入抓取替身并返回成功。

这说明拥有网页工具的调用者可以请求本机或内网地址；是否实际读到敏感内容取决于服务、网络及授权。修复：默认公网页面读取统一走受限出口，对 DNS 全部结果、重定向和浏览器回退一致校验；需要访问用户明确授权的内网站点时使用单独的域名与用途授权。对应 T06、T13、T20。

### CR04 电脑桥接 HTTP 层缺少 Origin 检查

**P1，服务接入。** `mcp_dsh_server.py:2640` 起支持查询参数 token 和 Bearer，`:2661` 与 `:2783` 返回通配 CORS，`:2715` 的 POST 路径没有 Origin 与 Host 校验；`:2672` 读取 Content-Length 时没有应用层上限。现有 token 降低了直接滥用的可能，但不能代替来源、请求大小与超时限制。

修复：本地首选 stdio；保留 HTTP 时绑定 loopback、校验 Host/Origin、使用 Authorization、限制正文大小与读取时间，URL 不携带密钥。历史 token URL 只作显式兼容迁移。MCP 的具体约束见[官方传输规范](https://modelcontextprotocol.io/specification/2025-11-25/basic/transports)。对应 T06、T13。

### CR05 MCP 版本协商回显任意客户端版本

**P2，协议兼容。** `mcp_dsh_server.py:2571` 至 `:2574` 将请求中的 protocolVersion 原样返回。隔离复现 R02 发送 `2099-01-01`，服务仍返回这一未实现的版本；`:2558` 忽略初始化通知，处理 tools/list 和 tools/call 前也没有完整连接生命周期守卫。

修复：使用固定版本的官方 MCP SDK，声明实际支持的版本和能力，按协商结果处理请求；未知版本不能假装支持。[生命周期规范](https://modelcontextprotocol.io/specification/2025-11-25/basic/lifecycle)要求返回实际支持的版本。对应 T13、T14。

### CR06 部分业务失败被包装为成功工具结果

**P1，结果真实性。** `mcp_dsh_server.py:2526` 至 `:2540` 在 handler 没有抛异常时统一返回 `isError: false`，而 `:700` 等分支直接返回“无法执行”的文本。隔离复现 R01 用返回失败文本的 handler 观察到 `isError: false`。

修复：统一 ToolOutcome，提供 ok、errorCode、retryable、artifactRefs 和必要的外部动作回执；业务失败明确映射为 MCP 错误结果。任务完成依据校验结果和产物，不能仅看进程退出码或自然语言。对应 T05、T11、T14。

### CR07 合同 MCP 构建源码不完整

**P1，构建阻塞。** `代码/合同助手/mcp/build.ps1:3` 至 `:8` 依赖 sibling `desktop/build.ps1` 及 ContractEngine、TemplateRules、AiService、BatchImport、ContractLibrary、MaterialCatalog、MaterialImport、Preferences、EmbeddedContent 九个类文件；当前主工程没有该 desktop 目录。其资源嵌入也依赖该目录。

已有 HTML 版与 `build.py` 是另一种交付，不能据此证明 C# MCP 可构建。修复：从用户有权使用的现有合同项目补齐准确版本与资源来源；用干净检出编译并校验金额、模板、预览和输出。对应 T02、T23。**先前“合同已有功能”的历史记录不等于当前仓库完整可复现。**

### CR08 外部运行环境与绝对路径耦合

**P1，产品独立性。** `mcp_dsh_server.py:288` 至 `:302` 从 Harness 桌面版 app.asar 的内部路径启动 CLI；`:1466` 至 `:1471` 的 Codex 调用默认依赖特定用户与 `.dsh` 内 Node 路径；`:580` 至 `:582` 的通知默认指向旧工作区。更换用户、磁盘或软件安装方式可能失效。

保留 Harness 为核心是用户要求；需要替换的是不稳定的定位和数据混用。修复：明确运行时安装来源、固定版本、独立 DSH_HOME、受支持 SDK/CLI、路径解析和启动自检。保留旧路径仅用于迁移读取，不作为新版本默认值。对应 T01、T04、T09。

### CR09 文件读取先读完整文件再截断

**P2，资源限制。** `mcp_dsh_server.py:778` 至 `:784` 用 `target.read_bytes()[:limit]`，且 max_bytes 缺少合理上限。隔离复现 R04 的替身文件在请求 16 字节时仍执行 1 MiB 的完整读取。实际遇到大文件会浪费内存，异常输入可能放大影响。

修复：有界流读取、负数与过大参数拒绝、类型和文本编码检查；大文件走分块或产物引用。对应 T14、T20。

### CR10 权限缺少服务端任务身份与委托范围

**P1，架构缺口。** 当前 `dsh-access.mjs` 在 Harness 会话侧过滤技能和工具，这是值得保留的保护；电脑桥接 `call_tool(params,cfg)` 只看到工具参数和服务全局配置，没有可靠的 requester、会话来源或子任务授权。服务 token 本身也不表达“谁可对哪个账号做哪件事”。

接入邮箱、外部 agent 和主动任务后，这个缺口会扩大。修复：权限网关持有可信任务上下文，授予短时、有限资源范围的能力；在真实动作边界检查。群成员不能通过委托 agent 获取主人的文件或邮件权限。对应 T07、T12、T29。不能仅在 prompt 中写禁止来代替。

## 与新架构有关的其他观察

根 `代码/项目/package.json` 只有运行信息，没有统一构建与检查命令，插件有自己的锁文件。现有双副本与临时维护脚本应逐步收敛成单一源码和可重复发布流程。相关问题进入 T03、T34、T36；不在本次审查中批量删除历史文件。

主项目部分文件已具备良好的限制与恢复措施，例如 Origin 检查、允许聊天校验、安全网页读取和发送回执。迁移不能把这些保护丢掉。`native-context.mjs` 通过 Harness 的 agents、sessions、agentPresets 与 tokenMeter 工作，保留它应同时建立版本适配测试。

本次没有对 Native Hook 的 C++、第三方数据库读取组件及所有依赖逐行审计；许可证说明与目录实际内容也需要进一步核对。扩展版本发布前通过 T03 和 T36 形成来源及分发清单。
