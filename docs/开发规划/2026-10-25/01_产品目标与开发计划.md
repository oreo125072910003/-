# 小助手产品目标与开发计划

版本：2026 年 10 月 25 日。目标平台：用户当前的 Windows 电脑，首先服务单一主人，支持多个通信与邮箱账号。用户已确认继续由 DeepSeek Harness 提供核心运行能力。

## 产品定位

小助手是一个有持续身份、了解主人、能连接外部世界并实际完成任务的个人桌面助手。她既能聊天，也能管理事情的来龙去脉、使用电脑上的资料、组织工作成果和调用专业帮手。她的价值来自长期使用中积累的理解与可靠执行。

“电脑上的灵魂”落实为六件可观察的事：你能随时找到她；她在不同入口保持一致的人格；她记得你允许保存的偏好和进行中的项目；她能将需求变成可追踪的行动；她知道何时需要主动提醒；她能通过扩展获得新的工作能力。电脑休眠、关机或断网时无法执行的工作，要明确显示并在恢复后按规则处理。

能力范围可以持续增长，但运行时始终受已安装工具、账号授权、模型能力、计算资源和数据质量约束。新增能力应有可重复的接入、测试和回退方式。开发目标是建立这种扩展机制，而不是预先罗列完所有用途。

## 已确定的产品边界

1. 小助手是独立 Git 项目，有自己的 EXE、界面、数据目录、插件配置、发布版本和恢复流程。
2. Harness 是核心运行依赖，负责模型会话、agent 执行及其运行日志。小助手通过适配层连接它，不重写相同的推理循环。
3. 首选由小助手托管独立的 Harness runtime 和 DSH_HOME，用户日常无需同时操作 Harness 桌面界面。具体版本能否支持这一体验，要先通过 T01 验证。
4. Harness 不可用时，仍可打开已保存的资料、查看任务、同步无需 AI 的邮件和设置账号；需要 AI 的工作显示等待引擎，不假装继续完成。
5. 邮箱以插件形式提供，可添加多个账号。标准 IMAP 邮箱走通用接入；Gmail、Microsoft 等按服务商能力提供授权适配。仅导入邮箱地址不能代替账号登录和授权。
6. 原有微信、表情、消息解析、合同等能力作为资产迁移，先保留已知可用行为，再逐步替换内部实现。

## 她应该有哪些长期能力

| 能力方向 | 用户能体验到什么 | 扩展方式 |
| --- | --- | --- |
| 持续陪伴 | 人格稳定，记住称呼与偏好，知道哪些事仍在进行 | 人格版本、可查看与纠正的记忆 |
| 统一沟通 | 微信、邮箱、桌面聊天接入同一个任务中心 | 通信通道和账号插件 |
| 处理工作 | 合同、报告、申请材料、表格、演示稿形成可编辑成果 | MCP 工具、模板与专业 Skill |
| 科研与学习 | 搜索文献、核对引文、阅读资料、解释问题、整理学习计划 | 检索源、阅读与写作技能 |
| 电脑助理 | 找资料、整理文件、操作授权软件、执行受控脚本 | 文件、浏览器与桌面操作适配器 |
| 长期项目 | 跟踪采购、课题、实验、报销或个人计划，知道下一步 | 项目库和带状态的工作流程 |
| 主动服务 | 重要邮件、临近截止、工作失败或监控变化时提醒 | 事件触发器、调度器与主动策略 |
| 专业协作 | 请另一个模型检查材料，或让编码 agent 处理开发任务 | Worker 注册表和委托机制 |
| 个人知识库 | 将邮件、文档、论文和已有成果按项目联系起来，回答时给出处 | 可增量索引、可撤销授权的数据源 |
| 新能力获得 | 识别当前不会做的事，提出安装工具或制作技能方案 | 扩展管理与开发工作区 |
| 日常生活 | 日程、清单、订阅、出行资料、资讯和兴趣项目 | 后续日历与服务插件 |
| 多种交流方式 | 后续可语音交流、查看选定窗口、展示桌面形象 | 可开关的输入输出模块 |

这些方向并非首版同时交付。微信、邮件和真实工作组成首批日常闭环；其他方向在稳定基础上扩展。语音、持续屏幕感知、多设备和开放插件市场属于后续版本。

## 可以逐渐长出的完整场景

以下是同一套能力基础可以形成的后续用途，用来检验架构是否足够开放，不作为首版一次性交付承诺。

| 场景 | 她可以把哪些事连起来 | 新增的主要依赖 |
| --- | --- | --- |
| 采购全过程 | 读取报价、比较型号、核对参数、拟合同、跟踪到货、准备验收和归档 | 供应商资料、采购与验收模板 |
| 课题研究 | 保存研究问题、持续检索、精读、追踪不同证据、整理想法并产出汇报 | 论文来源、阅读技能、课题项目库 |
| 实验助理 | 整理你提交的记录、关联仪器和样品、绘制数据、准备周报 | 明确的数据格式、绘图与仪器只读接口 |
| 长计算与仿真 | 整理输入、交给专业计算程序、观察进度、校验并汇总结果 | 可调用的仿真程序、计算资源和结果检查 |
| 工作事务 | 从通知中提取截止、准备材料、检查附件、形成提交清单 | 工作模板、账号与日程 |
| 个人资料管理员 | 找到“上次那份文件”、归类版本、指出重复或缺失附件 | 授权文件索引、版本和来源关系 |
| 学习陪伴 | 理解你的课程进度，基于资料讲解、安排复习、记录容易混淆的知识 | 课程资料、学习记录、复习流程 |
| 会议与沟通 | 接收录音或记录、整理决议和待办、协助写回复与后续材料 | 转写工具、会议授权、项目关联 |
| 自动汇报 | 从已经完成的工作中生成日报、周报和组会材料 | 项目事实、文档与演示稿工具 |
| 软件维护 | 让编码 agent 在隔离副本修复小工具，再检查、打包和展示结果 | 开发 worker、Git 与构建环境 |
| 信息观察 | 持续跟踪论文、供应商页面、软件任务或其他明确对象的变化 | 数据源、差异检测与提醒规则 |
| 内容与设计 | 组织文本、图像和演示稿，委托不同模型制作与审查 | 图像、排版、演示和品牌素材工具 |
| 电脑维护 | 检查指定服务、磁盘和备份，整理故障诊断和恢复建议 | 系统只读诊断及受控维护工具 |
| 个人日常 | 行程资料、清单、家庭文档和兴趣计划集中管理 | 日历、地图或相关服务插件 |
| 新工作学习 | 根据你做过的样例归纳流程，提出一份可复用技能草稿 | 样例、技能制作与验证流程 |

这些场景共享同一个主人身份、项目历史和成果库。例如，一封新报价邮件可以关联到几周前微信里讨论过的采购；一篇新论文可以关联到课题问题与已有实验记录。跨来源关联前先检查授权和事实来源，不能仅凭名字相似就合并人物、项目或账号。

她也应有“能力自知”：知道哪些工具已经连上、哪些登录过期、哪些工作需要专业软件、哪些结果还缺证据。不会做时保留目标和已完成部分，给出获取能力的具体路径，而不是只说“我做不了”或凭空声称完成。

## 怎样让新能力不需要重做软件

小助手以“能力注册表”发现工具、技能、工作流程和专业 agent。一次任务先看当前有哪些可用能力，再选择组合方式。缺少账号或工具时，显示具体缺口；有替代方式时给出可以实际执行的路径。

例如“帮我处理这份采购”可先读取邮件附件，提取货物信息，关联已有供应商资料，调用合同工具计算和生成，再交给另一个 agent 检查事实与格式，最后把草稿交给主人。以后加上发票、验收、报销插件，就能在同一采购项目中继续工作。

新能力的获得分为四种：接入一个外部工具；增加一份做事方法；把已有动作组合成流程；增加一个专业 worker。只有这些途径都无法满足时，才需要开发新的程序模块。对生产程序的修改通过隔离开发、测试和版本发布进入，不能让一次普通聊天直接改坏正在工作的自己。

## 用户界面

主界面围绕“和她说话、正在做什么、成果在哪里”组织。建议提供以下页面：

| 页面 | 主要内容 |
| --- | --- |
| 和小助手聊天 | 文字与附件，明确当前项目，展示任务进度和可打开的成果 |
| 我的事情 | 进行中、等待资料、已完成、失败和取消；支持继续、暂停调度与重试 |
| 项目与资料 | 课题、采购、材料、学习等项目；资料来源、版本、截止和下一步 |
| 收件与提醒 | 多账号邮件、重要变化和待处理事项；点击回到来源 |
| 记忆 | 她记住的偏好和事实，来源、修改、删除及哪些会话可以使用 |
| 能力 | 插件、MCP、Skill、工作流程、外部 agent 的安装状态与授权范围 |
| 设置与体检 | 模型连接、账号、费用、后台运行、数据目录、备份与可读错误提示 |

托盘提供打开、暂停主动提醒、暂停自动执行、查看连接状态和退出。暂停提醒与停止任务是不同操作；退出前展示仍在运行的工作。术语和内部端口只在高级诊断中出现。

## 一天的实际使用

早上，她按你设定的时间汇总新邮件和今天到期的事项。没有重要变化时保持安静；已有的提醒可合并，避免反复刷屏。

你在微信里说“用供应商这封报价做一份采购合同”。她把这件事登记到采购项目，读取你授权的邮件和模板，核对规格、数量和金额。缺少的真实信息列成一个问题；已能完成的整理继续推进。合同形成后先给你可编辑的草稿和核对表。

你说“再帮我看看这个方案有没有遗漏”。她选择一个有审查能力的 worker，只给它相关材料和必要权限。worker 的结果回到同一任务，她结合原始资料核对后向你汇报。其他 agent 不是绕过权限的通道。

晚上，你说“这个课题以后遇到相关论文就提醒我”。她保存明确的检索范围和提醒频率，后台按计划检查；有值得看的新文献时给出理由、来源和可打开的条目。电脑离线期间的检查标记为延后，恢复后合并处理。

## 授权与自主程度

目标是减少反复打扰。已授权资料的读取、草稿生成、任务内部整理和低风险的检查直接进行。授权设置按账号、项目、文件夹和动作保存，可以随时撤销。

对外发送、删除资料、安装执行型插件和付费调用采用明确规则。用户已明确要求的某次发送在目标与内容足够具体时可以直接执行；规则外的首次动作、未知收件人、扩大文件范围或超预算时才请求补充授权。确认卡要展示实际内容、目标和后果，不能让用户确认一个抽象的“是否允许 AI 操作”。

群聊、邮件正文和网页都是资料来源，不能赋予主人权限。主人记忆与群成员记忆分开；某群中收到的指令不能读取其他群记录、私人邮件或主人的本地文件。此处的授权是产品设计要求，本次规划不修改用户已有的授权。

## 分阶段交付

以下里程碑按验收推进。人员与依赖确定前不承诺日历日期；任务书给出人日估算，模型运行、用户登录、外部服务审核和长时间稳定性观察另计。

| 阶段 | 具体成果 | 用户怎么验收 | 退出条件 |
| --- | --- | --- | --- |
| M0 可复现基线 | Harness 版本接入结论、完整合同源码或明确缺口、现有行为样例 | 能说明现有版本怎么启动、哪些可用、哪些待修 | T01 至 T03 完成，选定受支持接入路线 |
| M1 独立桌面基础 | 小助手窗口、独立数据目录、任务保存、成果库、权限、MCP 与 Skill 管理 | 从桌面打开她，交一个附件任务，关掉再打开仍能看到记录 | 不混用个人 Harness 配置，失败和恢复可见 |
| M2 微信可靠接入 | 原微信能力迁入，任务来源绑定，回执、串台防护和故障诊断 | 私聊与群同时交任务，结果准确回到原处 | 通过多聊天、掉线和重启场景 |
| M3 多账号邮件 | 添加账号、导入账号设置、收信同步、搜索、摘要、附件和草稿 | 添加两种服务的账号，重启与断网后不漏记、不反复提醒 | 通用 IMAP 实测；Gmail/Graph 按账号条件测试并单列状态 |
| M4 工作与知识 | 合同、材料、文献三种闭环，以及项目资料与可编辑记忆 | 从资料生成可编辑文档；文献结果有真实来源；能继续上次项目 | 产物、事实核对、引用和记忆隔离验收通过 |
| M5 委托与主动工作 | 调用专业 agent、费用限制、计划任务和安静的主动提醒 | 一件事分给帮手后统一交付；指定监控只有重要变化才提醒 | 委托无越权，预算和终止有效，调度可恢复 |
| M6 日常使用候选版 | 安装包、升级与回滚、备份、诊断、稳定性观察 | 在新 Windows 用户环境安装；连续日常使用并能恢复备份 | 无未解决 P1，完成端到端和连续运行验收 |
| M7 持续扩展 | 能力制作台、日历、语音、选定屏幕理解和其他设备 | 每个扩展单独安装、关闭和验收 | 按实际需求逐个立项 |

M1 可以展示桌面和简单工作；M2 至 M4 逐步形成你能实际使用的版本。M6 才是本计划中“可以作为日常主力助手”的交付门槛。完成前一个阶段不是禁做所有后续工作，但不能用界面进度掩盖任务和权限基础未完成。

## 首版必须覆盖的事情

首个日常版本包括：独立桌面入口、稳定人格、持久任务与成果、原微信主要能力、可添加多个账号的邮件插件、合同与材料及文献工作流程、可管理的记忆、MCP 与 Skill 管理、至少一个外部 worker 接入、可取消的计划任务、费用记录、备份和诊断。

首版不追求开放插件市场、跨设备同步、自主改动生产代码、持续录屏、完全离线的高质量所有任务和所有邮箱零配置。这些目标需要额外条件；优先保证扩展接口已经留好。

## 工作量的初步判断

配套任务书将日常使用候选版拆成 35 项任务，另有 5 项持续扩展任务。候选版的初步合计是 **49 至 98 人日**，按每周五个完整开发日约 10 至 20 周。它反映软件工程与联调规模，不能直接换算为某个 AI 要运行多久。M0 完成后按实际 Harness 兼容性、合同源码完整性和账号条件重新估算；外部授权与稳定性观察等待另计。

不必等所有阶段结束才见到成果。M1 应先交付能打开、能执行简单工作且能保存记录的桌面版；M2、M3、M4 依次增加微信、邮箱和工作闭环。后续投资依据真实使用反馈决定。

## 验收标准与质量目标

| 方面 | 候选版目标 |
| --- | --- |
| 启动 | 在记录硬件配置的本机，界面冷启动目标 10 秒内可交互；AI 与网络连接状态单独展示 |
| 数据恢复 | 重启后已确认保存的任务、记忆和成果保留；运行中任务显示恢复状态，未知外部动作不自动重放 |
| 路由 | 跨两个微信聊天、两个邮箱账号及桌面的混合场景中，测试集不出现错收件人或越权资料 |
| 任务 | 每项工作有状态、来源、可打开产物和可读失败原因；进程正常退出不直接等于业务成功 |
| 邮件 | 支持断线重连、游标恢复、UIDVALIDITY 或历史游标失效重建，重复同步不会重复创建同一事项 |
| 工作成果 | 合同金额由确定性逻辑校验；材料不编造事实；文献带可核对标识与原始来源 |
| 自主工作 | 授权范围内少打扰；静默时段、合并提醒、取消计划和费用上限实际生效 |
| 运行稳定 | 在一套固定发布版本上做至少 72 小时观察；崩溃、网络切换和休眠唤醒有记录与恢复结果 |

上述数字是开发验收目标，不是已经测得的性能。实际耗时与成功率在 M0 建立样例、M6 记录硬件和外部条件后报告，不能把外部微信或邮箱故障藏进一个成功率。

## 开发组织与完成定义

每项任务都要留下源码、说明、必要的测试、实际验收结果与已知限制。单元检查、模拟接口、真实账号、安装包构建和长时间观察分开记录。只有相关验收通过才能把状态改为完成。

新增功能先使用模拟账号与脱敏资料验证，再在有授权的真实环境做最小闭环。旧链路保留至替代版本通过验收；迁移有备份和回退，不直接覆盖运行目录。依赖升级先测版本兼容矩阵。

开发工作通过 [04_开发任务书.md](04_开发任务书.md) 和 [tasks.json](tasks.json) 执行。每轮以“下一个能让你实际用起来的闭环”为目标，而不是不断堆积未联调的功能代码。
