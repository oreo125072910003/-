# 小助手开发任务书

版本：2026 年 10 月 25 日。与 [产品计划](01_产品目标与开发计划.md)、[架构规范](02_系统架构与扩展规范.md)及[代码审查](03_现有代码审查报告.md)配套。机器清单为 [tasks.json](tasks.json)。

## 执行原则

本任务书共 40 项任务，其中 M0 至 M6 共 35 项构成日常使用候选版，M7 是后续可选扩展。初始规划状态为 planned；2026 年 10 月 25 日已开始实施。当前各项状态及证据见下文和 tasks.json。首批可运行预览版不能等同于全部任务验收通过。

先解决构建、身份、任务和交付边界，再扩展业务。Harness 继续作为核心，产品自己的数据和配置独立。任务负责人在实施时填写；实现与复核可以由工程师或受控开发 agent 承担，但没有因此自动授权任何外部消息或真实账号操作。

任务状态使用 planned、in_progress、blocked、ready_for_review、accepted。accepted 必须有实现提交、验收证据与已知限制；进度按已经验收的可用闭环报告，不能按代码行数或平均任务数冒充功能完成率。

## 工作量与关键路径

M0 至 M6 的初步合计为 **49 至 98 人日**，按每周五个完整开发日约 10 至 20 周。该估算用于排顺序和识别规模，不是交付日期承诺；AI 辅助不能消除接口兼容、真实账号联调与恢复验证。外部授权、模型调用费用、数据补齐和稳定性观察等待另计。完成 T01 至 T03 后重估，每完成一阶段再更新剩余估算。

关键链路是 T01/T03 → T04/T05/T07/T08/T09 → T10/T11/T13/T15 → 微信与邮件 → 工作闭环 → 委托与调度 → 综合验收与安装。T02 是合同路线的构建前置条件。独立的资料收集、测试夹具和界面可以并行准备；账号、权限和出站实现必须遵守依赖。

## 第一个开发周期

第一批执行 T01、T02、T03。接着完成 T04、T05、T07、T08 和 T09，形成可保存身份与任务的 Harness 接入基础，再做 T10、T11 和 T15 的桌面闭环。T06、T12、T13、T14、T16 在向真实通道开放前补齐。此顺序不要求在一个聊天或一次运行内做完。

第一次用户演示只验证“打开小助手 → 提交一个脱敏附件工作 → 看进度 → 打开真实成果 → 重启后记录仍在”。随后才验证微信跨会话、多账号邮件和专业工作。演示需要标出哪些仍是模拟服务。

## 每项任务的共同完成定义

1. 实现遵守项目已有功能与兼容要求，变更可在 Git 中单独审阅。
2. 增加必要的失败与边界测试；低影响文案修改不另堆形式测试。
3. 留下执行命令、测试条件、实际结果、产物或日志引用。模拟与真实账号结果分开。
4. 有配置样例、错误提示、数据迁移或回退方式；不提交凭据和个人正文。
5. 源码、构建、部署和真机是不同状态，未经实测不声称完成。
6. 未经明确指令或有效规则，不进行真实对外发送、生产切换或扩大账号授权。

## M0 可复现基线

### T01 确定 Harness 接入与版本兼容

状态：in_progress。优先级：P0。依赖：无。初步估算：1 至 2 人日。

目标：选定小助手继续使用 Harness 核心的可维护接入路线。

实施内容：

- 只读记录本机 runtime、SDK、插件、profile 和安装来源的确切版本；不覆盖个人配置。
- 在隔离 DSH_HOME 中验证受支持 SDK/CLI 的启动、文本与附件、工具、权限问题、会话恢复、事件和终止；不满足时验证现有桥接兼容路线。
- 记录原生取消粒度、哪些审批可被应用接管、哪些工具会绕过产品网关；选定一组固定版本。

交付物：Harness 兼容矩阵及 ADR；最小连接验证程序与脱敏结果；受支持版本和安装方案。

验收：

- 明确列出可用、受限与不支持的能力，记录具体版本和真实测试结果。
- 用户个人 Harness home 未被改写；不再依赖 app.asar 内部路径作为正式入口。
- 未解决权限隔离或取消粒度前，相应产品功能明确关闭或限制。

审查关联：CR08、CR10。

### T06 实现密钥和网络边界

状态：in_progress。优先级：P1。依赖：T04。初步估算：1 至 2 人日。

目标：账号与工具凭据不散落在配置和日志中。

实施内容：

- 实现 secretRef 与 Windows 系统保护存储，配置只保存引用。
- 统一公开网页访问规则、逐跳地址校验、代理和浏览器回退限制。
- HTTP 接口校验 Host/Origin、大小、读取时限；移除默认 token URL；子进程环境变量采用允许清单。

交付物：secret-store；网络策略模块；脱敏和凭据迁移工具。

验收：

- 日志、错误、产物元数据和导出配置中无测试密钥。
- loopback、私网和恶意重定向按规则拦截；授权内网站点走独立规则。
- 凭据不可解密或授权过期时明确报错，不能回退保存明文。

审查关联：CR03、CR04。

- 每个失败都有可读原因与恢复路径；真实服务问题单列。
- 长时间观察另计等待，不把其时长混成人日估算。

### T34 构建安装升级和回滚交付

状态：planned。优先级：P1。依赖：T12、T15、T33。初步估算：2 至 3 人日。

目标：用户可以像普通软件一样安装和更新。

实施内容：

- 固定运行时与依赖，构建 Windows 安装包和校验清单。
- 安装向导处理 Harness 核心、工具依赖与路径；不要求改 YAML 或端口。
- 升级前做兼容检查和快照，支持失败回退；签名状态如实记录。

交付物：安装包；更新迁移程序；回滚说明。

验收：

- 新 Windows 用户环境可按向导完成安装并运行样例。
- 升级失败可回退，用户数据保留；卸载与删除数据是分开的选项。

<a id="t35"></a>

### T35 迁移旧环境并实现备份恢复

状态：planned。优先级：P1。依赖：T08、T19、T21、T26。初步估算：1 至 2 人日。

目标：迁移不丢数据，也不破坏正在使用的版本。

实施内容：

- 读取旧环境路径、配置、人格和必要状态，生成迁移预览及版本化备份。
- 使用 SQLite 一致性备份和产物清单，密钥按本机保护或重新授权处理。
- 先试迁移和回退演练，新链路通过后再切换，保留旧入口恢复方式。

交付物：迁移工具；备份与恢复界面；演练报告。

验收：

- 恢复后任务、记忆、成果和账号配置对应一致。
- 不直接复制正在写入的单个 WAL 数据库；不修改个人 Harness home。
- 旧运行目录切换需有可审阅预览，失败能恢复。

## 变更规则

用户的新目标可以增加任务、重排优先级或调整架构决定。先更新受影响的依赖与验收，再实施。产品定位、权限边界和数据所有权的变化应留下架构决策；一般界面实现和模块内部重构由执行者按本计划处理，无需反复向不懂开发的用户追问技术选型。
