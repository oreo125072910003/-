# 小助手 DSH 1.0.7

小助手的核心始终是 DeepSeek Harness（DSH），沿用已有登录、人格、微信授权与持续会话。

## 作为 DSH 插件使用

现已提供“小助手与微信”1.1.5 插件，将工作台、微信、任务、邮箱和能力管理放进 DSH；无需另开小助手桌面程序。完整版包含专用微信与消息读取环境，支持新 Windows x64 电脑安装，首次在新电脑登录微信后按向导连接。

从 [GitHub Releases](https://github.com/oreo125072910003/-/releases) 下载 `xiaozhushou-harness-host-1.1.5.tgz`，在 DSH 正式插件管理器安装。开发构建运行 `npm run package:dsh:full`，产物位于 `dist/dsh-plugin/1.1.5-full`；[插件说明](packages/dsh-plugin/README.md)包含安装方法、数据沿用规则与验证边界。

## 日常打开

独立桌面版：从 Releases 下载安装程序，按向导安装后使用桌面或开始菜单中的“小助手”。先打开并登录 DSH；微信保持登录即可。小助手会启动已配置的消息读取服务，暂时断线后自动等待恢复。

安装版使用当前 Windows 用户的程序目录，无需管理员权限；升级前正常退出旧版。已有数据库会自动发现，有多份数据时要求明确路径；卸载保留个人数据、微信环境和 DSH。独立安装版和 DSH 完整插件都附带专用微信 4.1.10.27、匹配的连接组件和 Python 读取环境。新电脑在“微信通信”页点击“准备并连接微信”，再扫码登录、识别账号并验证；已有连接继续沿用。两种入口沿用同一数据，不同时运行两份服务。

## 1.0.7 的补齐

- Windows 安装程序默认内置专用微信与完整读取环境，微信页明确显示准备与连接入口。
- 独立桌面与 DSH 复用同一个四步向导；已有连接不会被首次设置覆盖。
- 安装器在缺少微信组件时拒绝构建；验收实际准备微信环境并核对所有组件，而不只检查工作台程序。

## 1.0.6 的变化

- 采用“纸面工作桌”界面，突出工作输入、进行中任务和通信状态，减少重复身份、统计卡和状态提示。
- 合并两套样式，保留微信、邮箱、能力管理及窄窗口的完整操作。
- 共用界面服务契约、产品数据目录发现和图片元数据校验，避免不同入口的规则漂移。
- 提供 Windows 每用户安装器，保留旧数据和独立的卸载路径。
- 延续 1.0.5 的微信长会话修复、客户端控制、新邮件通知、长图局部阅读和自我完善逐项审批。

## 1.0 的变化

- 统一启动入口正确处理 Windows 中文路径，清理会影响桌面启动的开发环境变量。
- 自动补齐已有微信环境的读取服务；初次连接失败会继续等待，手动断开后保持断开。
- 两个不同聊天或任务可以并行；同一微信会话按顺序处理，继续使用原来的 DSH 上下文。
- 界面显示最近回复用时，长任务保留进度提示与附件交付记录。
- 余额不足、登录失效、接口地址错误和请求过于频繁有明确提示；未知投递结果保留待核对状态。
- 包含此前 0.3.13–0.3.16 的浏览器连接、附件交付和 DSH 组件更新修复，统一发布源码、程序和校验文件。

只处理连接后收到的新消息。重启不补发旧消息，发送结果不明时不自动重发；账号变化、授权变化或人工接管会暂停自动回复。DSH 账户额度、网络和微信登录状态仍需要有效。

## 升级与退出

升级前从旧小助手托盘退出，再打开新版。关闭窗口会收起到托盘，托盘菜单“退出小助手”才会完整退出。原电脑继续使用原数据；发布包不包含个人配置、账户密钥、聊天和邮件。

若 DSH 连接组件更新后提示等待重载，从 DSH 托盘完整退出后重新打开。电脑和浏览器操作继续使用已有的明确授权。

## 开发与验证

主工程为本目录。安装依赖后使用 `npm run check`、`npm test`、`npm run package`。分发构建使用 `XIAOZHUSHOU_DISTRIBUTION=1`，再运行 `npm run package:installer` 构建安装程序；`npm run package:dsh:full` 构建完整插件。构建产物通过 GitHub Release 发布，源码提交到 Git。
