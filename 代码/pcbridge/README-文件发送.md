# 微信文件发送：可用配置（2026-10-23 已验证）

## 结论

微信助手可以给主人私聊发**真实文件消息**。已验证送达：PDF（0.8–3.5 MB）、图片、文字。

## 关键组件

| 组件 | 路径 |
|---|---|
| MCP 服务 | `mcp_dsh_server.py`（端口 8765，`start_hidden.vbs` 启动） |
| UI 发送脚本 | `send_wechat_native.ps1` |
| 批量带校验发送 | `send_files_verified.ps1` |
| 标题基准图 | `_wx_title_<sha1前10>.png`（260×42） |

## 发送流程（send_wechat_native.ps1 -ScanRows）

1. `-NormalizeWindow`：窗口固定 1000×760 并临时置顶（TOPMOST），等待 2 秒。
2. 会话列表滚到顶部（滚轮上滚 10 格），保证第 0 行是置顶的私聊。
3. 逐行点击会话 → 截图标题区（x=0.30W, y=0.05H, 260×42）→ **原分辨率逐像素**比对基准图。
4. 判定：目标 diff ≤ 3 **且** 比对照聊天（群里只有一个好人）diff 好 ≥ 5 才发送。
5. 点输入框（0.55W, 0.62H）→ Ctrl+A/Delete 清空 → 剪贴板放文件 → Ctrl+V → 点发送按钮（0.937W, 0.945H）。
6. 去掉置顶。
7. 服务端查微信数据库：必须出现"发送时间之后的新文件消息"（type=25769803825）才算成功。

## 踩过的坑（勿重犯）

- **标题校验区域**：不能截右侧图标区（各聊天都一样，diff≈0.6 会误判）。必须截标题文字区（y≈0.05H）。
- **不要缩放到 192×48 比较**：两个不同标题的 diff 只有 8 左右，无法区分。用原分辨率逐像素。
- **并发调用**：多个 export_file 同时跑会抢窗口互相点乱 → 必须加 `_FILE_SEND_LOCK` 串行。
- **会话列表滚动后行号错位**：扫描前必须滚到顶部。
- **回车不能发送文件卡片**：要点击"发送"按钮。
- **窗口被其他窗口覆盖时**点击失效 → 发送前临时置顶。
- 发送失败会重试 3 次，仍失败才把 PDF 首页转图片兜底（图片走 hook，按 wxid 定向）。

## 限制

- 发送期间约 20–40 秒微信窗口被置顶，**期间不要操作微信**，否则会打断。
- hook 原生 API 没有发文件接口，文件只能走 UI 自动化。
- 目标私聊一定要置顶（第 0 行），否则扫描可能找不到。
