# 微信文件输入

0.3.10 在现有 bridge、controller、存储和 DSH 任务链路中保留普通 appmsg/6 与合并转发 appmsg/19 的文件引用。历史发现仅处理低 32 位类型为 49 的真实卡片，普通文字中粘贴 XML 不能变成文件授权。转发正文按历史资料传递，文件路径、CDN 凭据和原 XML 不进入模型提示。

文件 ID 由已核验账号、原 talker、原消息 fingerprint 和文件序号生成。每次读取重新核对 reader 账号、会话授权及原消息；新文件引用和历史文件引用采用同一规则。`sourceId/index` 等字段是结构化元数据，聊天正文中的路径和 URL 不参与文件解析。

本机固定 Python 子进程只查询既有鉴权 reader，复用其 Windows 凭据解码和必要的 NT 只读数据库代码，不启动另一个微信服务，不重新登录，不调用任意聊天 URL，不下载远程附件。源码或安装包必须能找到与当前 reader/Hook 地址匹配的既有 WeChatAgent 来源及其已配置 Python。安装包中的 Python 脚本显式解包到真实文件，避免将 ASAR 虚拟路径交给外部解释器。

有原消息 MD5 时，缓存文件需同时通过大小、消息摘要及返回 SHA256 检查。卡片没有摘要时，普通业务授权不开放按文件名扫描的兜底。仅在主人早已为该私聊开启电脑权限、且本轮实际保留本地文件/命令读取能力时，才允许使用微信 `file_hardlink_info_v4` 的唯一文件名/大小索引取得本机缓存 MD5；多种内容摘要、索引缺失或缓存变化均拒绝。该范围在读取前和保存快照前重新核对，消息参数不能自行打开它。此方式确认当前缓存版本，不把它说成卡片中不存在的原件摘要证明。

文件本体只在任务私有资料目录保存，公开消息不包含本机缓存路径。单文件最多 16 MiB，一轮最多 4 份微信文件，任务资料总量最多 64 MiB；缓存搜索、子进程、展开和文字提取均有上限。取消后不接纳迟到内容。失败的文件有明确状态，不能仅凭文件名猜测正文。

当前解析支持 DOCX、XLSX、带文字层 PDF 及常用文本。Excel 按 workbook 的关系映射读取工作表、单元格坐标和缓存值；不启动 Excel、不执行宏、不重算公式、不读取外部链接。旧 DOC/XLS、加密文件、扫描件 OCR、未下载或已失效附件尚不能保证读取。

已有 `xiaozhushou_read_document` 的 `path` 参数可使用 `wechat://files` 列出本轮原会话最近 100 条消息中的最多 40 个文件，再使用返回的 `readPath` 读取。内部形如 `wechat://file/<productMessageId>/<fileId>`；调用方不能另选账号或聊天。列表读取不会把历史消息重新提交为自动回复。当前不提供任意久远历史的分页检索。

实际验证覆盖普通 DOCX/XLSX、转发内已缓存 DOCX/XLSX，并仅记录大小、提取字符数、覆盖范围和校验方式，不保存正文到源码或日志。完整证据见 [0.3.10 记录](../../docs/开发记录/20261026_0.3.10微信文件读取与自主执行修复.md)。
