# WeChatAgent 微信功能直接复用对照

核对日期：2026-10-25。核对来源包括本工程 `代码/项目` 与用户指定的 `G:\wechat-deepseek\data\workspace` 源码。只读检查了公开程序源文件；没有把旧配置、凭据、微信数据库或聊天记录复制进本模块。

本模块的角色是给产品应用服务提供窄接口。旧 `HookOneBot`、`conversationId`、`onebotId`、`normalizeOneBotEvent`、表情策略与会话设置继续从原文件导入，没有重新建立一套账号或会话标识算法。未调用原适配器 `start()`，因此不会偷偷启动第二套旧 HTTP/OneBot 服务。原消息接收、策略和 SDK 插件应分别移入产品生命周期，不能只把目录复制进安装包就称为完成。

## 目前可调用的接口

| 能力 | 直接复用的原实现 | 本模块接口与状态 |
| --- | --- | --- |
| 读取/发送器健康、版本与账号一致性 | `HookOneBot.checkNative`、`hookAccountProblem` | `start`、`getStatus`，已离线验收；只有账号核对与 SSE 均成功才 ready |
| 本人实际微信昵称/微信号 | 原组件 native `POST /GetSelfProfile`；当前 `scripts/native-hook` 404 时用 reader contacts 精确本人记录 | `getProfile() -> {id,name,wxid,alias,source}`；状态含 account；来源区分 native/reader-contact，不采用助手设置昵称替代真实资料 |
| 好友/群聊名称搜索 | reader `/api/v1/contacts`；原 console `/api/contacts` | `getDirectory({kind,keyword,limit}) -> {kind,contacts:[{id,kind,name,ambiguous,allowed}]}`，只读元数据，包含未授权候选 |
| 已授权微信会话 | reader `/api/v1/sessions`、原 `conversationId` | `getSessions({limit:500}) -> {sessions:[{id,kind,name,allowed,ambiguous}]}` |
| 已授权聊天最近记录 | 原 `HookOneBot.resolveTarget/messages` -> reader `/api/v1/messages` | `getHistory({kind,target,limit:100}) -> {kind,target,name,messages,pagination:'latest-only'}`，无虚构翻页 |
| 文本/图片/表情/拍一拍/卡片接收 | 原 `HookOneBot.incoming` 与 `normalizeOneBotEvent` | `onMessage`；保留原 images 与 interaction；本版产品层需接对应展示 |
| reader 的真实消息 ID | reader `push_payload` 生成的 SHA256 rawid | 已修正接受 64 位 hex，保留数字 ID 兼容；有真实协议格式回归测试 |
| 文字发送与确认 | 原 `HookOneBot.action/send`、`TextDeliveryStore` | `sendText`，只在数据库 serverId 确认后返回成功；未知结果不重发 |
| 聊天图片静态预览 | reader `/api/v1/images/{id}`；原 `image-input.mjs` 的绑定、格式、大小、摘要规则 | `resolveImage({kind,target,id}) -> {id,mime,b64,sha256,bytes}`，最多 768 KiB；不直接暴露 reader 返回的任意文件路径 |
| 原生表情候选 | 原 `HookOneBot.action/get_sticker_list` | `getStickers({kind,target,query}) -> {enabled,stickers}`；可传 `start(config.stickerSettings)` 保留原全局/会话开关 |
| 原生表情发送/回执/防重 | 原 `HookOneBot.action/sendSticker` | `sendSticker({kind,target,id,deliveryId})`，保留原 receipt/media_type/reused 语义；未接产品 outbox/UI 前不能宣称用户入口完成 |
| 每聊天人格、群回应模式、表情/搜索/主动聊天/上下文开关与技能工具授权 | 原 console `chatSettingsSnapshot/applyChatSettings`、`conversation-policy.mjs` | `conversation-settings.mjs` 的 `readConversationSettings/updateConversationSettings`；返回候选配置，产品服务负责持久化及权限接线 |

`getHistory` 每条消息含 `message_id`（原 localId）、`external_id`（严格复用 reader push_payload 的 SHA256 rawid 规则）、`server_id`、`sender_id`（原 onebotId）、`sender_name`、`text`、`time`、`outgoing`、`message_type`。这样同一条历史及其 SSE 副本共用持久化去重标识。非文本采用原 parsedContent 展示说明，避免将内部 XML 当已解析内容。reader 当前 HTTP 路由只接收 limit，不接收 before/offset，因此本接口明确只提供最近记录，默认按时间升序显示最新一批。

本人资料允许显示本人 wxid/alias，便于知道登录的是谁；好友/群目录及聊天记录输出数字映射 ID，不返回对方原始 wxid。错误输出永远只含稳定代码，不输出令牌、电话号码或原生账号资料。原源码未提供可验证头像字段，暂不伪造头像 URL。

## 原工程已具备、仍需在产品中接上运行的部分

| 原有能力 | 源模块/原接口 | 产品接线要求 |
| --- | --- | --- |
| 每聊天独立的 Harness 会话、人设、上下文压缩与超时恢复 | `packages/dsh-social-bridge-plugin/native-context.mjs`；GET `/sessions`，POST `/configure`、`/compact`、`/followup`、`/context-maintenance` | 复用原插件与当前 Harness 支持入口；本模块 `getSessions` 是微信会话目录，不能冒充这里的 AI 会话状态 |
| 会话分组、创建/更名/删除/移动 | `session-groups.mjs`；GET `/session-groups`、POST `/session-groups/{create,rename,delete,move}` | 接原插件账户隔离和工作区权限，不能把微信群和 Harness 分组混为一类 |
| 按聊天分配已装 Skill/工具 | `dsh-access.mjs`、`conversation-policy.mjs`；GET `/dsh-catalog` | 继续复用原可分配工具筛选、每轮调用预算与拒绝未授权技能逻辑；只保存开关不等于已执行隔离 |
| 网页阅读、模型搜索、群友记忆、表情图库、主动聊天、上下文压缩 | `scripts/extension-status.mjs` 的 BUILTIN_FEATURES 与相应 policy/engine | 保留原设置结构和原生运行逻辑，分别接能力中心、会话设置与产品调度生命周期 |
| 表情池筛选、图库/标签/导入编辑删除 | reader `/api/v1/stickers/pool-status`、`/manage`、`/manage/image`、POST `/manage/{import,edit,delete}`、标签接口；`wechat_sticker_manager.py` | 管理操作会写原表情数据，必须明确属于产品数据并经产品服务；不能为复用而向旧个人目录写入 |
| 群改名后的稳定关联/歧义处理 | 原 reader group-bindings、console `/api/group-bindings` | 显示 ambiguous，保留原关联规则；重新关联是写操作，需要产品配置版本检查 |
| 微信数据库连接配置、换号、凭据保护、进程恢复 | `reader-setup.mjs`、`reader-account-state.mjs`、`process-recovery.mjs` | 不可复制真实密钥或直接修改旧运行环境；产品应有自己的凭据存储与启动状态 |
| 合并转发、引用回复、链接/文件/小程序卡片 | `wechat-events.js`、reader `push_payload` | 原解析继续有效；产品显示与附件接收能力需要单独接线，不能把外部文字或路径提升为本地文件授权 |
| 拍一拍、群提醒、自然参与/仅@回应、频率控制 | 原 `incoming`、`social-engine.js`、`chat-policy.js` | 复用原触发和速率逻辑；当前本模块不自行开启自动回复 |

普通图片发送是 native `SendImageMsg` 低层路由，原 `HookOneBot.action` 没有相应带确认回执的公开 action。当前桥不把调用该路由成功就标记送达，也不把它包装为已经可靠迁移。表情发送则已有独立数据库回执链，已直接复用。

## 验证边界

`node --test tests/wechat-transport.test.mjs` 覆盖真实 localhost HTTP/SSE 协议替身、原 SHA256 rawid、启动取消、落库失败停收、本人资料、联系人/会话命名、授权历史、图片绑定与内容摘要、原表情回执/防重，以及原会话配置结构。未向真实微信发送任何消息。root 的真实只读连接与最终桌面接线结果由 root 独立记录。
